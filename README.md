# План питания

План питания и тренировок на недели 8–23 (12 октября 2026 - 31 января 2027) в виде PWA для iPhone.

Сайт: https://avemepls95.github.io/nutrition-plan/

На iPhone: открыть сайт в Safari, «Поделиться» → «На экран „Домой“». Правки хранятся на телефоне, в localStorage приложения с главного экрана (отдельно от Safari).

## Структура

- `docs/`: сайт, публикуется через GitHub Pages (ветка `main`, папка `/docs`).
- `docs/plan.js`: данные плана, генерируются из PDF командой `python tools/extract_plan.py <путь к PDF>`.
- `docs/foods.js`: калорийность продуктов по умолчанию, разбор состава на продукты с количеством, пересчёт состава под свою калорийность и граммовка порций моих блюд. Пишется руками.
- `docs/backup.js`: копия данных с телефона в файле, её разбор и запись на устройство.
- `docs/disk.js`: отправка копии в папку приложения на Яндекс Диске и учёт правок, которых там ещё нет.
- `tools/make_icons.py`: иконки приложения, шрифт для них лежит в `tools/fonts/`.

Калорийность продуктов в `docs/foods.js` подобрана так, чтобы сумма продуктов каждого блюда без кофе отличалась от ккал блюда в плане не больше чем на 1,5 ккал. Проверка: `node tools/check_foods.js`. Тесты разбора и пересчёта состава и копии данных: `node --test`.

Настройки и правки на телефоне: `np.v1.edits` (правки приёмов пищи и добавленные приёмы пищи со временем, ккал в правках записаны по калорийности продуктов по умолчанию и без кофе), `np.v1.weights` (вес по неделям), `np.v1.kcal` (своя калорийность продуктов с днём, с которого она действует, день, с которого продукт удалён, и названия, которые дал продукту пользователь), `np.v1.dishes` (мои блюда: название, состав, «Порцией» и вписанный вес готового блюда), `np.v1.theme` (тема).

В справке, раздел «Данные», все эти ключи выгружаются в файл JSON и загружаются из него. Загрузка заменяет их на устройстве целиком. В файле метка приложения `app`, версия формата `version`, время выгрузки `exported` и значения ключей в `data`.

## Копия на Яндекс Диске

Если в справке вписан ключ Яндекс Диска, через 5 с после правки (и при запуске, если прошлая копия не ушла) тот же файл уходит в папку приложения на Диске («Приложения/<название приложения в Яндекс OAuth>/План питания 2026-11-07 18-40-05.json»). Каждая копия ложится отдельным файлом. Пока на устройстве нет данных (новый телефон до загрузки копии), копия не уходит. Чтобы вернуть данные, нужный файл сохраняют из Диска в «Файлы» и загружают в справке.

Ключ и учёт отправленного хранятся в `np.v1.disk` (`token` ключ, `rev` номер последней правки, `sent` номер правки в последней копии, `at` время последней копии, `error` итог неудачной попытки). В файл копии этот ключ не попадает. В коде ключа нет, потому что репозиторий публичный и GitHub не пропускает пуш с OAuth-ключом Яндекса.

Ключ выдаёт своё приложение в Яндекс OAuth: на oauth.yandex.ru «Создать» → «Для доступа к API или отладки», в доступах только «Доступ к папке приложения на Диске». Кнопка «Получить ключ» в справке открывает страницу `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID приложения>` (ClientID стоит в её ссылке в `docs/index.html`). Страница показывает ключ (строка `y0_…`), его копируют в поле в справке. Отозвать ключ можно на id.yandex.ru, раздел «Безопасность».

Service worker отдаёт файлы из кэша и в фоне проверяет свежие, поэтому новая версия сайта появляется на телефоне со следующего запуска. При каждой публикации меняйте версию `CACHE` в `docs/sw.js`, новый файл сайта добавляйте в `ASSETS`.
